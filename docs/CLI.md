## Синтаксис

```text
sudo usfc [команда] [аргументы] [опции]
```

- Без команды открывается меню.
- Команда — ровно одна, и это первое слово, которое не опция. Опции можно
  писать до и после неё.
- У каждой команды свой набор опций. Чужая опция — ошибка с кодом `2`
  и объяснением, например `--json не относится к команде apply`.
- Значение опции пишется через пробел или через `=`: `--swap 2048`
  и `--swap=2048` равнозначны. Значение, похожее на опцию, — ошибка:
  `--lang --yes` не поставит язык «--yes».
- Нужен root: usfc меняет системные файлы. Функция `usfc()` в `.bashrc`
  добавляет `sudo` сама; в скриптах пишите `sudo usfc …`.

## Установщик

`install.sh` ставит usfc в `/opt/vps-setup`, создаёт команду
`/usr/local/bin/usfc` и запускает её. Себе установщик забирает только флаги
из таблицы ниже, всё остальное передаёт в `usfc`.

```bash
curl -fsSL https://raw.githubusercontent.com/SkyDeaD/UbuntuServer-Fast-Configuration/main/install.sh | sudo bash
```

| Флаг | Что делает |
|---|---|
| `--branch <ветка>`, `-b <ветка>` | ставить из ветки, по умолчанию `main` |
| `--help`, `-h` | справка установщика |
| `--` | всё после него уходит в `usfc`, даже совпадающее с флагами установщика |

С командой меню не открывается и терминал не нужен — так usfc работает
из cloud-init:

```bash
curl -fsSL https://raw.githubusercontent.com/SkyDeaD/UbuntuServer-Fast-Configuration/main/install.sh \
  | sudo bash -s -- apply web --yes
```

`bash -s --` обязателен: без него bash не передаст аргументы скрипту из
трубы. Без команды и без терминала установщик меню не открывает: сообщает,
что usfc установлен, и выходит с кодом `0`.

## Общие опции

Работают с любой командой и без неё.

| Опция | Что делает |
|---|---|
| `--lang ru\|en` | язык этого запуска. Не запоминается: постоянный язык меняется клавишей `L` в меню |
| `--no-update` | не проверять обновление usfc |
| `--verbose` | показывать полный вывод команд вместо спиннера |
| `--dry-run` | без команды — меню в режиме предпросмотра; с `apply` и `firewall` — см. ниже |
| `-h`, `--help` | справка; `usfc help <команда>` — по одной команде |
| `-V`, `--version` | версия |

Обновление проверяется только при запуске меню. Командам (`apply`, `audit`
и остальным) оно не нужно: их результат никто не смотрит в реальном
времени, а фоновый запрос задерживал бы выход.

## Команды

### `usfc apply`

```text
usfc apply <что> [--dry-run] [--yes] [--config <файл|https://…>] [--set КЛЮЧ=значение] [флаги ответов]
```

Применяет пункты без меню и без вопросов по ходу. Ответы на вопросы пунктов
берутся из флагов, файла ответов и дефолтов пунктов — в таком порядке
приоритета.

| Опция | Что делает |
|---|---|
| `<что>` | что применять: профиль, `all`, id или номера пунктов. См. [Что писать в apply](#что-писать-в-apply). Можно не писать, если в файле ответов есть `ITEMS=` |
| `--dry-run` | показать, что было бы сделано, ничего не меняя. Код возврата — `0`, даже если пункты «не применились»: в сухом прогоне они и не должны |
| `-y`, `--yes` | отвечать «да» и там, где у вопроса дефолт «нет». Исключение — перезапуск Docker (`--docker-restart`): он перезапускает контейнеры, и `--yes` его не включает |
| `--config <файл\|https://…>` | взять ответы из [файла ответов](#файл-ответов). URL — только `https://` |
| `--set КЛЮЧ=значение` | задать любой ключ файла ответов прямо в командной строке. Можно повторять |
| флаги ответов | `--swap 2048`, `--ufw`, `--allow 443` и другие, см. [таблицу](#ответы-на-вопросы-пунктов) |

Поведение, которое стоит знать:

- **Уже применённые пункты пропускаются.** В меню повторный выбор пункта
  с `⇄` означает «выключить», и без этого правила повторный запуск из
  cloud-init выключал бы то, что просили включить. Исключение — пункт с явно
  заданными новыми настройками: `ufw` с `--allow`, `--ping`/`--no-ping` или
  `--docker-firewall`, `unattended` с `--reboot-time` или
  `--reboot-with-users`, `sshhardening` с `--ssh-port`. Такой пункт
  применяется заново и только добавляет новое.
- **`newuser` пропускается всегда**: нужны имя и пароль.
- **`sshhardening` без `--ssh-port` пропускается** с сообщением: закрыть себе
  доступ к серверу по чужому файлу ответов — не та цена за автоматизацию.
  С `--ssh-port` пункт только переносит порт; вход по ключу и запрет пароля
  настраиваются в меню.
- **UFW без согласия не включается.** Согласие — `--ufw`, `UFW=Y`, `--yes`
  или явный список портов (`--allow`, `UFW_ALLOW`): кто перечислил порты,
  тот знает, что остальное закроется. Уже включённому UFW согласие не нужно.
- **Флаг для пункта, которого нет в списке, — ошибка** с кодом `2`:
  `--allow задан, а пункта ufw в списке нет`. Тот же ключ в файле ответов
  ошибкой не считается: один файл обычно делят все ноды.
- **`--yes` включает «перезагружать, даже если кто-то вошёл»**
  (`--reboot-with-users`), если пункт `unattended` в списке. Не нужно — добавьте
  `--no-reboot-with-users`.
- В конце печатается сводка «пункт — результат — причина», а если правились
  системные файлы, — команда отката: `sudo usfc restore <метка>`.

### `usfc firewall`

```text
usfc firewall [--allow <порты>] [--deny <порты>] [--from <IP>] [--ping|--no-ping]
              [--docker-firewall|--no-docker-firewall] [--config <файл>] [--set КЛЮЧ=значение]
              [--dry-run] [--yes]
usfc firewall ping on|off
usfc firewall docker on|off
```

Файрвол UFW без меню. Без опций печатает сводку: политику, правила, состояние
ping и Docker.

| Опция или аргумент | Что делает |
|---|---|
| `--allow <порты>` | открыть порты. Выключенный UFW включается: у терминала — с подтверждением, с `--yes` или без терминала — сразу |
| `--deny <порты>` | убрать разрешение для портов. Есть только у `firewall` |
| `--from <IP>` | применить `--allow` и `--deny` только к адресу или подсети: `10.0.0.5`, `10.0.0.0/8` |
| `--ping`, `--no-ping` | отвечать или не отвечать на ping |
| `ping on\|off` | то же, что `--ping` и `--no-ping` |
| `--docker-firewall`, `--no-docker-firewall` | подчинить ли опубликованные порты Docker-контейнеров правилам UFW |
| `docker on\|off` | то же, что `--docker-firewall` и `--no-docker-firewall` |
| `--config`, `--set` | взять ключи `UFW_*` из файла ответов или командной строки |
| `--dry-run` | показать, что было бы сделано |
| `-y`, `--yes` | не спрашивать подтверждение включения UFW |

Формат портов — через запятую: `443` (это TCP), `51820/udp`,
`1000:2000/tcp`. SSH-порт сервера разрешается первым и не закрывается
никогда, даже `--deny`.

Как это устроено:

- ping выключается правкой `/etc/ufw/before.rules`: в блоках ICMP `ACCEPT`
  меняется на `DROP` и добавляется правило для `source-quench`. В
  `/etc/ufw/before6.rules` закрывается только `echo-request`: остальной
  ICMPv6 нужен самому IPv6 (обнаружение соседей). `ping on` возвращает
  файлы байт в байт.
- Docker публикует порты в обход UFW. `docker on` добавляет в
  `/etc/ufw/after.rules` схему ufw-docker (цепочка `DOCKER-USER`), после чего
  снаружи к контейнерам проходит только разрешённое. Работает для IPv4
  и iptables-бэкенда Docker.

### `usfc audit`

```text
usfc audit [--json]
```

Проверяет сервер и ничего не меняет: место и inode, память и подкачку,
упавшие systemd-юниты, открытые порты против правил UFW (TCP и UDP, включая
порты Docker в обход UFW), вход по паролю и root-логин, чужие drop-in sshd,
ping, security-обновления, нужна ли перезагрузка, сроки сертификатов.

| Опция | Что делает |
|---|---|
| `--json` | машиночитаемый отчёт |

Формат JSON:

```json
{
  "usfc": "5.0.0",
  "generated_at": "2026-10-23T04:00:00+00:00",
  "host": "node-1",
  "os": "Ubuntu 24.04.3 LTS",
  "lang": "ru",
  "summary": { "ok": 9, "warn": 3, "crit": 0, "total": 12 },
  "findings": [
    {"id": "ssh.password_auth", "section": "...", "level": "warn", "text": "...", "hint": "..."}
  ]
}
```

`id` и `level` (`ok`, `warn`, `crit`) не зависят от языка — на них и стоит
завязывать мониторинг. `text` и `hint` — на языке интерфейса. `hint`,
`value` и `unit` есть только у находок, где они имеют смысл. Значения в
примере выше иллюстративные.

### `usfc export`

```text
usfc export > node.conf
```

Печатает файл ответов по текущему состоянию сервера: `ITEMS=` из
применённых пунктов и значения их настроек, а в конце — ту же настройку
одной командой установки. Настроили одну ноду в меню — следующую можно
настроить одной строкой.

- Секреты (`CF_TOKEN`, `TG_TOKEN`) не выгружаются никогда: только
  закомментированный ключ без значения.
- Имя хоста — тоже комментарий: у каждой ноды своё.
- Разрешения UFW для отдельных адресов в файл не входят (`UFW_FROM` один на
  все порты) и печатаются комментарием, чтобы не потерялись.
- Только чтение, как и `audit`.

### `usfc list`

Печатает профили и id всех пунктов.

### `usfc backups`

Печатает снимки конфигов из `/var/backups/usfc`, свежие снизу. Снимок
делается перед каждой правкой системного файла.

### `usfc restore`

```text
usfc restore [метка] [--yes]
```

Возвращает конфиги из снимка. Метка — имя каталога снимка вида
`ГГГГММДД-ЧЧММСС-PID`, список — `usfc backups`.

| Опция | Что делает |
|---|---|
| `[метка]` | какой снимок вернуть. Без метки спросит её у терминала; без терминала — ошибка с кодом `2` |
| `-y`, `--yes` | не спрашивать подтверждение |

Перед откатом снимается ещё один снимок, чтобы откат можно было откатить.
Файлы, которых до usfc не было, при откате удаляются.

### `usfc help`

```text
usfc help [команда]
```

Общая справка или подробная — по одной команде: `usfc help apply`. То же,
что `-h` и `--help`.

### `usfc version`

Печатает версию. То же, что `-V` и `--version`.

## Что писать в apply

Профиль, `all`, id или номера пунктов через запятую, вперемешку:
`usfc apply web,bbr,motd`. Номера — как в меню.

| Профиль | Что входит |
|---|---|
| `minimal` | basepkgs cli unattended |
| `web` | basepkgs cli docker nginx certbot fail2ban unattended zram ufw |
| `dockerhost` | basepkgs cli docker dockerlog fail2ban unattended zram ufw |
| `secure` | basepkgs fail2ban unattended sshhardening ufw |

| № | id | Пункт |
|---|---|---|
| 1 | `newuser` | Пользователь + sudo |
| 2 | `hostname` | Имя, время, NTP |
| 3 | `bbr` | TCP BBR |
| 4 | `basepkgs` | Базовые пакеты |
| 5 | `cli` | CLI-утилиты + starship |
| 6 | `fastfetch` | fastfetch |
| 7 | `motd` | Приветствие при входе |
| 8 | `tmux` | tmux |
| 9 | `docker` | Docker + Compose |
| 10 | `nginx` | nginx-full |
| 11 | `certbot` | Certbot + плагины |
| 12 | `dockerlog` | Docker log rotation |
| 13 | `journald` | Лимит журнала systemd |
| 14 | `fail2ban` | fail2ban |
| 15 | `notify` | Уведомления в Telegram |
| 16 | `unattended` | unattended-upgrades |
| 17 | `zram` | ZRAM + swap + earlyoom |
| 18 | `sshhardening` | SSH hardening |
| 19 | `ufw` | UFW firewall |

Пункты применяются в порядке таблицы, а не в порядке, в котором вы их
перечислили. Подробно о каждом — в [MANUAL.md](MANUAL.md).

## Ответы на вопросы пунктов

Каждый вопрос, который пункт задаёт в меню, можно ответить заранее: флагом
`apply`, ключом файла ответов или `--set КЛЮЧ=значение`. Флаг сильнее файла,
файл сильнее дефолта пункта.

У флагов «да/нет» есть пара «нет»: `--sysctl` — да, `--no-sysctl` — нет.
В файле ответов «да» пишется как `Y`, `yes`, `true`, `on`, `1` или `да`, «нет» —
`N`, `no`, `false`, `off`, `0` или `нет`. Любое другое значение — ошибка, а не
тихое «нет».

| Флаг | Ключ | Пункт | Значение | Что задаёт |
|---|---|---|---|---|
| `--swap` | `SWAP_MB` | zram | целое, МБ, от 64 | размер резервного swap-файла |
| `--zram` | `ZRAM_PERCENT` | zram | 1..400 | размер zram, % от RAM |
| `--zram-reconfigure`, `--no-zram-reconfigure` | `ZRAM_RECONF` | zram | да/нет | перенастроить zram, настроенный вручную |
| `--sysctl`, `--no-sysctl` | `SYSCTL` | zram | да/нет | `vm.swappiness=80`, `vm.vfs_cache_pressure=50` |
| `--nginx-autostart`, `--no-nginx-autostart` | `NGINX_AUTOSTART` | nginx | да/нет | запустить nginx и включить автозапуск |
| `--docker-autostart`, `--no-docker-autostart` | `DOCKER_AUTOSTART` | docker | да/нет | запустить Docker и включить автозапуск |
| `--lazydocker`, `--no-lazydocker` | `LAZYDOCKER` | docker | да/нет | поставить lazydocker |
| `--docker-restart`, `--no-docker-restart` | `DOCKER_RESTART` | dockerlog | да/нет | перезапустить Docker под лимит логов — перезапустит контейнеры. `--yes` его не включает |
| `--certbot-cf`, `--no-certbot-cf` | `CERTBOT_CF` | certbot | да/нет | плагин Cloudflare (DNS-01, wildcard) |
| — | `CF_TOKEN` | certbot | токен | API-токен Cloudflare с правом `Zone:DNS:Edit`. Секрет: флага нет |
| `--certbot-tls`, `--no-certbot-tls` | `CERTBOT_TLS` | certbot | да/нет | TLS-заготовки в `/etc/letsencrypt` |
| `--ufw`, `--no-ufw` | `UFW` | ufw | да/нет | включить UFW |
| `--allow` | `UFW_ALLOW` | ufw | порты | открыть порты: `443,51820/udp,1000:2000/tcp`. В файле — через пробел или запятую |
| `--from` | `UFW_FROM` | ufw | IP или подсеть | открывать порты только для этого адреса |
| `--ping`, `--no-ping` | `UFW_PING` | ufw | да/нет | отвечать на ping; `--no-ping` — не отвечать |
| `--docker-firewall`, `--no-docker-firewall` | `UFW_DOCKER` | ufw | да/нет | подчинить порты Docker-контейнеров UFW |
| `--hostname` | `HOSTNAME` | hostname | имя | имя сервера: `node-1.example.com` |
| `--timezone` | `TIMEZONE` | hostname | `Area/City` | часовой пояс: `Europe/Moscow`, `UTC` |
| `--journal-max` | `JOURNAL_MAX_MB` | journald | целое, МБ | предел журнала systemd |
| `--motd-clean`, `--no-motd-clean` | `MOTD_CLEAN` | motd | да/нет | отключить стандартное приветствие и скрипты провайдера |
| `--starship` | `STARSHIP_PRESET` | cli | `minimal`, `git`, `powerline` | вид промпта |
| `--starship-prod`, `--no-starship-prod` | `STARSHIP_PROD` | cli | да/нет | боевой сервер: имя хоста в промпте красным |
| `--ssh-port` | `SSH_PORT_NEW` | sshhardening | `22` или `1024..65535` | перенести SSH на этот порт |
| `--reboot-time` | `REBOOT_TIME` | unattended | `ЧЧ:ММ` или `off` | перезагрузка после обновлений в это время; `off` — никогда |
| `--reboot-with-users`, `--no-reboot-with-users` | `REBOOT_WITH_USERS` | unattended | да/нет | перезагружать, даже если кто-то вошёл |
| — | `TG_TOKEN` | notify | токен | токен Telegram-бота от @BotFather. Секрет: флага нет |
| `--tg-chat` | `TG_CHAT` | notify | chat_id или `@канал` | куда слать: `123456`, `-100…`, `@channel` |
| `--notify` | `NOTIFY_EVENTS` | notify | `ssh,ban,reboot` | о каких событиях слать, любое подмножество |

Секреты (`CF_TOKEN`, `TG_TOKEN`) не имеют флагов: командную строку видно
любому пользователю в `ps`. Передавайте их файлом ответов с правами `600`.
`--set CF_TOKEN=…` отклоняется с кодом 2 по той же причине.

### Перенос SSH-порта

`--ssh-port` переносит порт в два шага, чтобы не потерять доступ:

1. Первый запуск: SSH слушает оба порта. UFW разрешает новый, fail2ban
   следит за обоими, `ssh.socket` перезапускается, вход на новом порту
   проверяется на `127.0.0.1`. Провал проверки — полный откат.
2. Вы проверяете вход на новом порту из своей машины.
3. Второй запуск той же команды закрывает старый порт.

```bash
sudo usfc apply sshhardening --ssh-port 2222   # шаг 1: слушаются 22 и 2222
ssh -p 2222 user@server                        # шаг 2: проверить с другой машины
sudo usfc apply sshhardening --ssh-port 2222   # шаг 3: 22 закрыт
```

В меню шаг 3 — это вопрос «вход на новом порту работает?» в том же пункте.

## Файл ответов

Текстовый файл `КЛЮЧ=значение`, по строке на ключ. Ключи — из
[таблицы выше](#ответы-на-вопросы-пунктов), плюс `ITEMS`.

```ini
# node.conf — пример
ITEMS=basepkgs,cli,docker,zram,ufw
SWAP_MB=2048
ZRAM_PERCENT=75
UFW=Y
UFW_ALLOW="443 51820/udp"
UFW_PING=N
TIMEZONE=Europe/Moscow
TG_TOKEN=123456:ABC-replace-me
TG_CHAT=123456789
NOTIFY_EVENTS=ssh,ban
```

Правила разбора:

- Файл читается построчно и не исполняется: `--config` из непроверенного
  места не должен уметь запускать команды.
- `#` начинает комментарий до конца строки — в том числе внутри значения.
- Пробелы вокруг значения отбрасываются, одна пара кавычек `"…"` или `'…'`
  снимается.
- **Неизвестный ключ — ошибка** с кодом `2`: опечатка `UWF=Y` иначе молча
  оставила бы сервер без файрвола. Неверное значение — тоже ошибка.
- `ITEMS` используется, только если `<что>` не задано в командной строке.
- `--config https://…` скачивает файл с таймаутом 20 секунд. `http://`
  не принимается: в файле бывают токены. URL в лог не пишется.

Готовый файл по уже настроенному серверу печатает
[`usfc export`](#usfc-export).

## Коды возврата

| Код | `apply`, `firewall` | `audit` | остальные команды |
|---|---|---|---|
| `0` | всё применилось, или применять было нечего, или это сухой прогон | важных проблем нет | успех |
| `1` | часть пунктов или действий не удалась | есть важные находки (`crit`) | ошибка выполнения |
| `2` | ошибка в аргументах или файле ответов | ошибка в аргументах | ошибка в аргументах |

Старые формы 4.x (`--apply`, `--audit`, `--list`, `--backups`,
`--restore`) завершаются с кодом `2` и печатают готовую новую строку.

## Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `USFC_LANG` | — | язык этого запуска, `ru` или `en`; то же, что `--lang` |
| `USFC_NO_UPDATE` | — | непустая — не проверять обновление; то же, что `--no-update` |
| `USFC_VERBOSE` | — | непустая — полный вывод команд; то же, что `--verbose` |
| `USFC_APT_LOCK_TIMEOUT` | `300` | сколько секунд ждать блокировку dpkg. На свежем сервере её минутами держит `unattended-upgrades` |
| `USFC_REPO_RAW_BASE` | raw-ссылка на `src` ветки `main` | откуда брать модули и обновления — для своего форка или проверки ветки |
| `USFC_KEEP_LOCALE` | — | непустая — не переключать локаль на `C.UTF-8` |
| `USFC_BRANCH` | `main` | ветка для установщика; то же, что `--branch` |
| `NO_COLOR` | — | непустая — без цвета. Цвета нет и при `TERM=dumb` или выводе не в терминал |

## Готовые команды

Посмотреть, что сделает профиль, ничего не меняя:

```bash
sudo usfc apply web --dry-run
```

Новая нода одной командой — пакеты, Docker, память, файрвол без ping:

```bash
curl -fsSL https://raw.githubusercontent.com/SkyDeaD/UbuntuServer-Fast-Configuration/main/install.sh \
  | sudo bash -s -- apply basepkgs,cli,docker,zram,ufw --allow 443,51820/udp --no-ping --swap 2048 --yes
```

Новая нода по файлу ответов с вашего сервера:

```bash
curl -fsSL https://raw.githubusercontent.com/SkyDeaD/UbuntuServer-Fast-Configuration/main/install.sh \
  | sudo bash -s -- apply --config https://example.com/node.conf --yes
```

Замените `https://example.com/node.conf` на адрес своего файла.

Снять файл ответов с настроенного сервера:

```bash
sudo usfc export > node.conf
```

Открыть порт только для одного адреса:

```bash
sudo usfc firewall --allow 5432 --from 10.0.0.5
```

Перезагрузки после обновлений — в 4:30, только если никто не вошёл:

```bash
sudo usfc apply unattended --reboot-time 04:30 --no-reboot-with-users
```

Аудит в мониторинг раз в сутки по cron:

```bash
sudo usfc audit --json > /var/lib/node_exporter/usfc.json
```

Откатить конфиги:

```bash
sudo usfc backups
sudo usfc restore 20261023-040000-3691 --yes
```

Замените `20261023-040000-3691` на метку из вывода `usfc backups`.

# Переход с usfc 4.x на 5.0

<p align="center"><b>🇷🇺 Русский</b> · <a href="MIGRATION-5.en.md">🇬🇧 English</a></p>

В 5.0 режимы стали командами: `usfc --apply web` теперь `usfc apply web`.
Совместимости со старыми флагами нет — они завершаются с кодом `2`
и печатают готовую новую строку. Эта страница — для тех, у кого usfc уже
стоит на серверах или вызывается из cloud-init, cron и Ansible.

## Что произойдёт само

usfc обновляется при каждом запуске меню. Когда 5.0 попадёт в `main`,
серверы с 4.x получат его при следующем `usfc`. Само обновление ничего на
сервере не меняет: пункты не применяются заново, конфиги не переписываются.

Что сломается без вашего участия:

- **Скрипты со старыми флагами.** `usfc --audit` в cron и `--apply` в
  cloud-init начнут завершаться с кодом `2`. Список замен — ниже.
- **Ничего больше.** Сервисы, файрвол, sshd и своп продолжают работать
  как были настроены в 4.x.

## Перед обновлением

1. Найдите вызовы usfc в своих скриптах:

   ```bash
   grep -rn 'usfc --\|install.sh.*--apply' /etc/cron* /var/lib/cloud /path/to/ansible 2>/dev/null
   ```

   Замените `/path/to/ansible` на каталог своих плейбуков.

2. Перепишите каждый вызов по [таблице](#было--стало).
3. Проверьте новую строку сухим прогоном: `sudo usfc apply web --dry-run`.

## Было → стало

| 4.x | 5.0 |
|---|---|
| `usfc --apply web` | `usfc apply web` |
| `usfc --apply=web` | `usfc apply web` |
| `usfc --apply all --dry-run` | `usfc apply all --dry-run` |
| `usfc --apply zram --yes` | `usfc apply zram --yes` |
| `usfc --config f.conf` | `usfc apply --config f.conf` |
| `usfc --config f.conf --apply web` | `usfc apply web --config f.conf` |
| `usfc --audit` | `usfc audit` |
| `usfc --audit --json` | `usfc audit --json` |
| `usfc --list` | `usfc list` |
| `usfc --backups` | `usfc backups` |
| `usfc --restore` | `usfc restore` (нужен терминал) |
| `usfc --restore <метка> --yes` | `usfc restore <метка> --yes` |
| `… \| sudo bash -s -- --apply web` | `… \| sudo bash -s -- apply web` |
| `usfc --help`, `usfc --version` | без изменений; также `usfc help`, `usfc version` |

Старая строка подсказывает новую сама:

```text
$ sudo usfc --audit --json
usfc: в 5.0 режимы стали командами. Вместо этого:
  usfc audit --json
```

## Что изменилось в поведении

Эти изменения не ломают строку, но меняют результат.

- **`usfc audit` возвращает `1` при важных находках** (`crit`). В 4.x код
  был всегда `0`. Если cron-задача проверяет код возврата, она начнёт
  сообщать о проблемах — это и задумано.
- **Пункты из командной строки сильнее `ITEMS=`.** В 4.x `ITEMS=` из файла
  ответов перебивал `--apply`. Теперь `ITEMS=` используется, только если
  в командной строке пункты не заданы.
- **`--config` без `apply` — ошибка.** В 4.x он молча игнорировался вне
  `--apply`.
- **Значения в файле ответов проверяются.** `NGINX_AUTOSTART=yse` в 4.x
  молча означал «нет», теперь это ошибка с кодом `2`. «Да» — `Y`, `yes`,
  `true`, `on`, `1`, `да`.
- **`--lang` с неверным значением — ошибка**, а не тихий русский.
- **UFW в пакетном режиме включается.** В 4.x пункт `ufw` в `--apply`
  молча пропускался даже в профилях `web` и `secure`. Теперь он включается,
  если есть согласие: `--ufw`, `UFW=Y`, `--yes` или список портов `--allow`.
  Без согласия — пропускается с предупреждением. **Проверьте, что ваши
  профили с `--yes` не закроют нужные порты:** откройте их через `--allow`.
- **`--yes` больше не перезапускает Docker** в пункте `dockerlog`: перезапуск
  останавливает контейнеры. Нужен — добавьте `--docker-restart`.
- **Вопросы с дефолтом «нет» в пакете больше не превращаются в «нет»
  молча.** TLS-заготовки certbot, автозапуск nginx и Docker, перенастройка
  zram задаются заранее — в меню вопросом, в `apply` — флагом или ключом.
  Полный список — в [CLI.md](CLI.md#ответы-на-вопросы-пунктов).
- **Флаг для пункта, которого нет в списке, — ошибка.** `usfc apply docker
  --swap 2048` завершится с кодом `2`: `--swap` относится к `zram`.

## Что меняется на уже настроенных серверах

Обновление само ничего из этого не делает. Изменения приходят, когда вы
снова применяете пункт — меню показывает такие пункты со статусом `!`.

### SSH hardening: новый файл drop-in

4.x писал `/etc/ssh/sshd_config.d/10-hardening.conf`. У sshd побеждает
первое значение ключа, поэтому любой файл провайдера, который сортируется
раньше (например `00-*.conf`), молча перебивал запрет пароля.

5.0 пишет `00-usfc-hardening.conf` и при применении удаляет старый файл.
На сервере с 4.x пункт показывает «! старый 10-hardening.conf — примени
пункт заново».

1. Откройте меню: `sudo usfc`.
2. Выберите пункт **18 «SSH hardening»** и пройдите вопросы.
3. Если usfc найдёт чужие строки, которые перебивают hardening, он покажет
   «файл:строка → значение» и предложит закомментировать их. Без согласия
   пункт не применяется.

После рестарта sshd usfc сверяет все ключи через `sshd -T`. При
расхождении он откатывает свой файл и называет файл, который победил.

### Своп: приоритет в fstab

В 4.x строка свопа в `/etc/fstab` правилась одним `sed`, который понимал
только форму `<путь> none swap sw`. Строки с `defaults`, `sw,nofail`,
`pri=5`, `UUID=` и `LABEL=` оставались без `pri=10`, хотя пункт сообщал
«приоритет 10». После перезагрузки своп поднимался с приоритетом по
умолчанию и мог использоваться раньше zram.

5.0 видит это: пункт **17 «ZRAM + swap + earlyoom»** показывает «!
приоритет свопа не записан в fstab». Выберите его — он исправит строку и не выключит
zram.

### Блоки в .bashrc

Пункты `cli` и `fastfetch` пишут блоки в `~/.bashrc`. В 5.0 у обоих новые
версии: в `cli` — функции `ports`, `dps`, `extract`, `myip` и пресеты
starship, у `fastfetch` — запуск только при входе по SSH и не внутри tmux.
Пункты показывают «блок устарел» или «автозапуск устарел». Выберите пункт,
чтобы обновить блок.

### fail2ban

4.x перезаписывал `/etc/fail2ban/jail.local`. 5.0 его не трогает и пишет
свой `/etc/fail2ban/jail.d/usfc-sshd.local` с `backend = systemd` — на
Debian 12 без этого jail не находил лога. Старый `jail.local` продолжает
работать, пока вы не примените пункт заново. Пункт с `⇄`: в меню повторный
выбор его выключает, поэтому чтобы переписать конфиг — выключите пункт и
включите снова.

### Снимки и откат

Снимки 4.x в `/var/backups/usfc` остаются и откатываются командой
`usfc restore <метка>`. Снимки 5.0 вдобавок помнят файлы, которых до usfc
не было, и при откате удаляют их.

## Если что-то пошло не так

- Вернуть конфиги: `sudo usfc backups`, затем
  `sudo usfc restore <метка>`.
- Что делать с конфликтами sshd, свопом и логом — в
  [TROUBLESHOOTING.md](TROUBLESHOOTING.md).
- Остаться на 4.x: 4.x проверяет обновление при каждом запуске, включая
  `--apply` и `--audit`, и обновляется из `main`. Отключается это только
  переменной `USFC_NO_UPDATE=1` в каждом вызове. Установка из тега
  (`install.sh --branch v4.2.0`) этим путём не проверялась.
